# discord-rs — Ataulfo bot

A Rust Discord bot that replies whenever a message starts with the word
**`ataulfo`**, forwarding the rest of the message to a custom
OpenAI-compatible AI provider. The bot's personality is an editable text file
that is hot-reloaded on every message.

## How it works

```
user: ataulfo what's the best mango?
bot:  (reply generated by your AI provider, using personality.txt as the system prompt)
```

- **Trigger:** `ataulfo` as the first word (case-insensitive). `ataulfos` does
  not trigger; `Ataulfo, hola` does.
- **Reply or mention to continue:** replying to one of the bot's own messages —
  or @mentioning the bot — triggers a response *without* the keyword, so a
  back-and-forth flows naturally.
- **Short-term memory:** the bot remembers the last few messages per channel
  (capped by `HISTORY_LIMIT`, default 12), tagged with each speaker's name, and
  feeds them to the model as conversation history. Memory is in-process only and
  resets on restart.
- **Personality:** edit `personality.txt` — changes apply on the next message,
  no restart needed.
- **Provider:** any OpenAI-compatible `/v1/chat/completions` endpoint.

## Setup

1. Copy the env template and fill it in:

   ```sh
   cp .env.example .env
   ```

   | Variable        | Description                                                        |
   | --------------- | ------------------------------------------------------------------ |
   | `DISCORD_TOKEN` | Bot token from the Discord Developer Portal.                       |
   | `AI_BASE_URL`   | Host root of your provider (bot appends `/v1/chat/completions`).    |
   | `AI_API_KEY`    | API key sent as `Authorization: Bearer …`.                         |
   | `AI_MODEL`      | Model name your provider expects.                                  |
   | `AI_MAX_TOKENS` | *(optional)* Cap on reply length, passed only if set.              |
   | `AI_TEMPERATURE`| *(optional)* Sampling temperature, passed only if set.             |

2. In the [Discord Developer Portal](https://discord.com/developers/applications),
   under **Bot → Privileged Gateway Intents**, enable **Message Content Intent**
   (required to read message text).

3. Invite the bot to your server with the **bot** scope and "Send Messages" /
   "Read Message History" permissions.

4. Run it:

   ```sh
   cargo run --release
   ```

## Editing the personality

Open `personality.txt` and write the system prompt that defines how the bot
behaves. It is read fresh on every message, so save and the next reply uses it.

## Swapping the AI provider format

All provider-specific code lives in `src/ai.rs`. If your provider isn't quite
OpenAI-compatible, adjust the request body and response structs there — the
rest of the bot is unaffected.
